# Strings – Immutability

## What Does Immutable Mean?

**Immutable** means:

Once a **String object** is created, its **value cannot be changed**.

You can create a **new String**, but you **cannot modify an existing one**.

---

## Example

```java
String s = "hello";
s = s + " world";
```

What actually happens:

1. `"hello"` object is created.
2. `"hello world"` is created as a **NEW object**.
3. Variable `s` now points to the **new object**.
4. The old `"hello"` object still exists in memory until garbage collected.

Memory model:

Before:
s → "hello"

After:
s → "hello world"

The original object is **not modified**.

---

## Why Strings Are Immutable

### 1. String Pool Optimization

String literals are stored in the **String Pool**.

```java
String a = "abc";
String b = "abc";
```

Both `a` and `b` point to the **same object**.

This is safe only because strings are **immutable**.

If strings were mutable:
- Changing `a` would also change `b`
- That would break program correctness

---

### 2. Security

Strings are used in:

- File paths
- Database URLs
- Network connections
- Class loading

If strings were mutable:
- Their values could be modified after validation
- This would create serious security issues

---

### 3. Thread Safety

Immutable objects are **automatically thread-safe**.

Multiple threads can use the same String without synchronization.

---

## Internal Reason for Immutability

Internally, String stores characters in an array.

Older Java:
- `char[] value`

Newer Java:
- `byte[] value` (memory optimized)

This internal array is:

- **Private**
- **Not accessible directly**
- **Never modified after object creation**

Java does not provide any method that changes this internal array.

All modification-like operations create **new objects**.

---

## Important Methods That Do NOT Modify the Original String

```java
s.concat("x");
s.substring(1);
s.toUpperCase();
```

All of these return a **new String**.

Correct usage:

```java
s = s.concat("x");
```

---

## Performance Implication

This is inefficient:

```java
String s = "";
for (int i = 0; i < 1000; i++) {
    s = s + i;
}
```

Because:

- Each concatenation creates a **new object**
- Many temporary Strings are created

Better approach:
Use **StringBuilder** when doing repeated modifications.

---

## Key Rules

- A String object **cannot be modified after creation**.
- Any operation that seems to modify a String actually creates a **new object**.
- Immutability enables **String Pool reuse**.
- Immutability improves **security and thread safety**.

---

## Core Mental Model

String = Object in Heap  
Object contains internal character array  
Internal array is never modified  
All "changes" create new String objects
