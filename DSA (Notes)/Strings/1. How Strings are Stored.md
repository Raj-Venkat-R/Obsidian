# Strings – How Strings Are Stored (Java)

---

## 🔹 What is a String?

A **String** is a sequence of characters.

Conceptually:
```
"hello"
→ 'h' 'e' 'l' 'l' 'o'
```

But in Java:

> A String is NOT just a character array.  
> It is an **object** that internally contains a character array  
> (or a byte array in newer Java versions for memory optimization).

---

# 🔹 Object vs Reference (VERY IMPORTANT)

When you write:

```java
String s = "hello";
```

There are TWO things involved:

### 1️⃣ Object
- The actual String instance stored in **Heap memory**
- Contains:
  - Internal character array
  - Metadata (like cached hash value)

### 2️⃣ Reference
- Variable `s`
- Stores the **memory address** of the object
- Does NOT store characters directly

Visual model:

```
Stack:
s  ───────────►  (address)

Heap:
[String Object]
   ↓
['h','e','l','l','o']
```

👉 The object stores data.  
👉 The reference stores the address.

---

# 🔹 What is Inside a String Object?

Internally (simplified view):

Older Java:
```
String object
 ├── char[] value
 ├── int hash
 └── other metadata
```

Java 9+:
```
String object
 ├── byte[] value
 ├── encoding info
 ├── int hash
 └── metadata
```

This is an internal optimization to reduce memory usage.

For you logically:
> String stores characters internally in an array.

---

# 🔹 String vs char[]

### Character Array
```java
char[] arr = {'h', 'e', 'l', 'l', 'o'};
```

- Primitive array
- Mutable
- No built-in string methods

---

### String
```java
String s = "hello";
```

- Object
- Immutable
- Has methods (`length()`, `substring()`, `equals()`, etc.)
- Stored in heap

---

# 🔹 Where Are Strings Stored?

All objects in Java are stored in **Heap memory**.

Inside heap, there is a special area:

> 🔹 **String Pool (String Constant Pool)**

---

# 🔹 Case 1: String Literal

```java
String a = "hello";
String b = "hello";
```

Steps:
1. Java checks String Pool.
2. If `"hello"` does not exist → create it.
3. If it exists → reuse it.

Memory:

```
Heap
 ├── String Pool
 │     "hello"
 └── Other objects

a → "hello"
b → "hello"
```

Only ONE object exists.

---

# 🔹 Case 2: Using `new`

```java
String s1 = "hello";
String s2 = new String("hello");
```

Steps:
1. `"hello"` literal stored in String Pool.
2. `new String("hello")` creates a NEW object in normal heap area.

Memory:

```
Heap
 ├── String Pool
 │     "hello"
 ├── Normal Heap
 │     new String("hello")

s1 → pool object
s2 → new heap object
```

Now TWO objects exist.

---

# 🔹 Why Java Reuses String Literals

Because:
- Strings are **immutable**
- Safe to share
- Saves memory
- Improves performance

---

# 🔹 Comparing Strings

## 1. Using `==`

```java
String a = "hello";
String b = "hello";

System.out.println(a == b);   // true
```

`==` compares **memory addresses (references)**.

---

## 2. Using `new`

```java
String a = new String("hello");
String b = new String("hello");

System.out.println(a == b);   // false
```

Different heap objects → different addresses.

---

## 3. Correct Way: `.equals()`

```java
a.equals(b);  // true
```

`.equals()` compares **character content**, not references.

---

# 🔹 Comparing Characters (Letter by Letter)

```java
s1.charAt(1) == s2.charAt(2)
```

This works because:
- `charAt()` returns a **primitive char**
- `==` works correctly for primitives

Use:
- `==` for primitives
- `.equals()` for String objects

---

# 🔹 Important Example (Reference Behavior)

```java
String a = "hello";
String b = a;
```

- Only ONE object exists.
- Two references point to same object.
- `a == b` → true

---

# 🔹 Key Rules (Memorize)

- String is an **object**
- Variables store **references**, not actual string data
- String literals are stored in **String Pool**
- `new String()` creates a new heap object
- `==` compares references
- `.equals()` compares values
- `charAt()` returns primitive char

---

# 🔹 Core Mental Model

> String = Object in Heap  
> Variable = Reference to that object  
> Internally contains character array  
> String literals reused via String Pool
