# Rate Monotonic Scheduling (RMS)

## Explanation

Rate Monotonic Scheduling is a fixed priority pre-emptive scheduling algorithm for periodic real-time tasks.

Priority Assignment Rule:
- Smaller period → Higher priority
- Larger period → Lower priority
- Priorities are fixed throughout execution

Given Tasks:

| Task | Execution Time (C) | Period (T) |
|------|--------------------|------------|
| T1   | 3                  | 20         |
| T2   | 2                  | 5          |
| T3   | 2                  | 10         |

---
## Assumptions

1. All tasks are periodic.
2. Deadlines are equal to periods.
3. Tasks are independent.
4. Preemption is allowed.
5. Context switch time is negligible.

___
## Step 1: Hyperperiod

Hyperperiod = LCM(20, 5, 10) = 20

---

## Step 2: Priority Order

T2 (T=5)  → Highest priority  
T3 (T=10) → Medium priority  
T1 (T=20) → Lowest priority  

Priority Order:

T2 > T3 > T1

---

## Step 3: CPU Utilization

U = (3/20) + (2/5) + (2/10)

U = 0.15 + 0.4 + 0.2  
U = 0.75 (75%)

RMS bound for n = 3:

U ≤ 3(2^(1/3) − 1) ≈ 0.78

Since 0.75 < 0.78, the task set is schedulable.

---

## Step 4: Scheduling (0 to 20)

Release Times:

T2 → 0, 5, 10, 15  
T3 → 0, 10  
T1 → 0  

Execution Order:

0–2   → T2  
2–4   → T3  
4–5   → T1  
5–7   → T2  
7–9   → T1  
9–10  → Idle  
10–12 → T2  
12–14 → T3  
14–15 → Idle
15–17 → T2  
17–20 → Idle

## Step 5: Deadline Verification

T2 deadlines: 5, 10, 15, 20 → Met  
T3 deadlines: 10, 20 → Met

# Final Conclusion

Priority Order: T2 > T3 > T1  
CPU Utilization: 75%  
All deadlines satisfied within hyperperiod (0–20).  

Therefore, the task set is schedulable under Rate Monotonic Scheduling.
