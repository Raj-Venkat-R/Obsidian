# Authentication and Authorization Mechanisms in Web Applications

In web applications, **security** is very important because users share personal data like passwords, bank details, emails, and documents. To protect this data, two main mechanisms are used:

- **Authentication**
- **Authorization**

Even though both sound similar, they serve different purposes.

---

## 1. Authentication (Who are you?)

Authentication is the process of verifying the identity of a user.

In simple words, it checks:
> “Are you really the person you claim to be?”

For example:
- When you log into Gmail using your email and password.
- When you enter OTP received on your phone.
- When you use fingerprint unlock.

If the credentials are correct, the system allows you to log in.

### Common Authentication Techniques Used in Web Applications

1. **Username and Password**
   - Most common method.
   - User enters username/email and password.
   - Password is stored in encrypted (hashed) format in database.
   - Example: Facebook login.

2. **Multi-Factor Authentication (MFA)**
   - Uses two or more verification methods.
   - Example:
     - Password + OTP
     - Password + Fingerprint
   - Provides extra security.

3. **One-Time Password (OTP)**
   - A temporary password sent to mobile/email.
   - Valid only for a short time.
   - Common in banking websites.

4. **Biometric Authentication**
   - Uses fingerprint, face recognition, or retina scan.
   - Mostly used in mobile-based web apps.

5. **Token-Based Authentication**
   - After login, server gives a token (like JWT – JSON Web Token).
   - The browser stores the token.
   - Token is sent with every request.
   - Server verifies token instead of asking password again.

6. **Session-Based Authentication**
   - After login, server creates a session ID.
   - Session ID is stored in browser cookies.
   - Used in traditional websites.

7. **OAuth / Social Login**
   - Login using Google, Facebook, or GitHub.
   - User does not create a new password.
   - The third-party service verifies identity.

---

## 2. Authorization (What can you do?)

Authorization happens **after authentication**.

It checks:
> “Now that we know who you are, what are you allowed to access?”

Example:
- A normal user can view products.
- An admin can edit or delete products.
- A student can view marks.
- A teacher can update marks.

So even if two users are authenticated, they may have different permissions.

---

## Common Authorization Mechanisms

1. **Role-Based Access Control (RBAC)**
   - Access is given based on user role.
   - Example:
     - Admin
     - Manager
     - User
   - Very common in web applications.

2. **Permission-Based Access Control**
   - Specific permissions are assigned.
   - Example:
     - Read
     - Write
     - Delete

3. **Attribute-Based Access Control (ABAC)**
   - Access is given based on attributes like:
     - Location
     - Time
     - Department
   - Example: Only employees inside office network can access data.

4. **Access Control Lists (ACL)**
   - List of users who can access a specific resource.

---

## Difference Between Authentication and Authorization

| Authentication | Authorization |
|---------------|---------------|
| Verifies identity | Grants permissions |
| Happens first | Happens after authentication |
| Example: Login | Example: Access control |

Simple example:
- Authentication is like showing your ID card at college gate.
- Authorization is like being allowed to enter only your department lab.

---

## Conclusion

In web applications, authentication and authorization work together to ensure security.

- Authentication confirms the user's identity.
- Authorization decides what the user can access.
- Modern web apps use techniques like password login, OTP, tokens, OAuth, RBAC, and session management.
- Proper implementation prevents unauthorized access and protects sensitive data.

Thus, both authentication and authorization are essential security mechanisms in web applications.
