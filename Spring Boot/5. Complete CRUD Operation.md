# Problem Summary

Building a complete CRUD REST API in Spring Boot using controllers, HTTP method annotations, and data passing techniques.

Input:
- A running Spring Boot project with Spring Web dependency
- Basic understanding of what a controller is

Output:
- A fully working CRUD API with GET, POST, PUT, DELETE endpoints
- Verified via Postman

- Understand how to pass data via URL, query params, and request body before moving forward

# Spring vs Spring Boot
```
Java
  └── Spring Framework (makes Java development easier)
        ├── Spring Boot (makes Spring even easier — auto configuration)
        ├── Spring Security (authentication & authorization)
        ├── Spring Data (database access)
        └── Spring Web (REST API building)
```

| Layer | Problem it solves |
|---|---|
| Raw Java | Base language — building APIs with raw Java is very complex |
| Spring | Removes Java boilerplate — but needs a lot of manual configuration |
| Spring Boot | Removes Spring configuration — auto-configured, just start building |

> "Spring Boot is an opinionated wrapper around Spring Framework that eliminates boilerplate configuration so you can start building immediately."

# REST API — Complete Controller
```java
@RestController
@RequestMapping("/todo")
public class ToDoController {

    // GET → /todo/get
    @GetMapping("/get")
    public String getToDo() {
        return "To Do List";
    }

    // POST → /todo/create
    @PostMapping("/create")
    public String createToDo(@RequestBody String body) {
        return body;
    }

    // PUT → /todo/update
    @PutMapping("/update")
    public String updateToDo(@RequestBody String body) {
        return body;
    }

    // DELETE → /todo/delete/{id}
    @DeleteMapping("/delete/{id}")
    public String deleteToDo(@PathVariable int id) {
        return "Deleted ID: " + id;
    }
}
```

# Annotations Explained

## `@RestController`
- Marks this class as a REST API controller
- Every method returns data directly (JSON, plain text)
- Combination of `@Controller` + `@ResponseBody`
- Comes from Spring Web dependency
- **`public` access modifier is required on every method — without it Spring cannot access the method and returns 404**

## `@RequestMapping("/todo")`
- Sets the base path for the entire controller
- Every method inside inherits it automatically
- Avoids repeating `/todo` on every method
```java
// Without @RequestMapping
@GetMapping("/todo/get")
@PostMapping("/todo/create")
@DeleteMapping("/todo/delete")

// With @RequestMapping("/todo")
@GetMapping("/get")
@PostMapping("/create")
@DeleteMapping("/delete")
```

# HTTP Methods

| Method | Annotation | Has Body | Purpose |
|---|---|---|---|
| GET | `@GetMapping` | ❌ No | Fetch / read data |
| POST | `@PostMapping` | ✅ Yes | Create new data |
| PUT | `@PutMapping` | ✅ Yes | Full update — replaces everything |
| PATCH | `@PatchMapping` | ✅ Yes | Partial update — only changed field |
| DELETE | `@DeleteMapping` | ❌ No | Delete data |

## PUT vs PATCH

**PUT** — send entire object, everything gets overwritten:
```json
{
  "name": "Arun",
  "phone": "9999999999",
  "address": "Chennai"
}
```

**PATCH** — send only what changed:
```json
{
  "phone": "9999999999"
}
```

# Three Ways to Pass Data

## 1. `@PathVariable` — Identify a specific resource
```java
@GetMapping("/{id}")
public String getToDo(@PathVariable int id) {
    return "Todo ID: " + id;
}
```

URL → `localhost:8080/todo/5`

- Name inside `{}` must match parameter name
- If names differ, specify explicitly:
```java
@GetMapping("/{todoId}")
public String getToDo(@PathVariable("todoId") int id)
```

## 2. `@RequestParam` — Filter or search
```java
@GetMapping("/search")
public String search(
    @RequestParam String keyword,
    @RequestParam int page
) {
    return "Searching: " + keyword + " Page: " + page;
}
```

URL → `localhost:8080/todo/search?keyword=java&page=1`

**URL structure:**
```
/search?keyword=java&page=1&sort=asc
        |           |       |
        ?           &       &
        separates   next    next
        path from   param   param
        params
```

| Symbol | Purpose |
|---|---|
| `?` | Separates path from parameters — used once |
| `&` | Separates each additional parameter |
| `=` | Separates key from value |

## 3. `@RequestBody` — Send complex or sensitive data
```java
@PostMapping("/create")
public String createToDo(@RequestBody String body) {
    return body;
}
```

- Data sent in request body — not visible in URL
- Used for POST, PUT, PATCH
- Later replaced with a proper Java class instead of raw String

---

# Security Rule — Never Use @RequestParam for Sensitive Data

URLs are visible in:
- Browser address bar
- Browser history
- Server logs
- Network DevTools
```
# Never do this
/api/login?username=arun&password=mypassword123  ❌
```

Always use `@RequestBody` with `@PostMapping` for login and sensitive data:
```java
@PostMapping("/login")
public String login(@RequestBody LoginRequest request) {
    // username and password safe in body
}
```

# API Versioning
```
/api/v1/projects
/api/v2/projects
```

- Just a naming convention — no functional difference between `v1` and `1.0`
- Allows old and new API versions to run simultaneously
- Existing users don't break when you release new version
- **Don't add versioning yet — keep it simple during development**

# CRUD — The Foundation of Every API

**CRUD = Create Read Update Delete**

| Operation | HTTP Method | Endpoint |
|---|---|---|
| Create | POST | `/todo/create` |
| Read | GET | `/todo/get` |
| Update | PUT | `/todo/update` |
| Delete | DELETE | `/todo/delete/{id}` |

Every backend API — DevShell, any project — is just CRUD on different data.

# Common 404 Causes & Fixes

| Cause | Fix |
|---|---|
| Typo in URL | Check URL carefully — case sensitive |
| Wrong HTTP method in Postman | Match annotation — POST for `@PostMapping` |
| Missing base path from `@RequestMapping` | Include full path in URL |
| Server not restarted after code change | Stop and `mvn spring-boot:run` again |
| Method missing `public` modifier | Add `public` to every endpoint method |

# Key Takeaways
- Spring Boot sits on top of Spring which sits on top of Java — each layer makes development easier
- `@RequestMapping` on the class sets base path — no need to repeat it on every method
- GET and DELETE have no body — use `@PathVariable` or `@RequestParam`
- POST, PUT, PATCH have a body — use `@RequestBody`
- Never send passwords or sensitive data via URL — always use `@RequestBody` with POST
- `?` separates path from params, `&` separates multiple params
- `@PathVariable` = identify resource, `@RequestParam` = filter/search, `@RequestBody` = send data
- Every method in a controller must be `public` — missing it causes 404
- CRUD is the foundation of every backend API you will ever build
