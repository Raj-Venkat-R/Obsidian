# Key Concepts Learned

## Group, Artifact, Name, Package Name — What Are They?

These are Maven project identifiers.

**Group** → `com.devshell`
- Your organization or domain name reversed
- Like a namespace — groups all your projects under one identity
- Convention: reverse domain (com.google, com.amazon, com.devshell)

**Artifact** → `devshell-backend`
- The name of this specific project/module
- Becomes the name of your generated .jar file
- Should be lowercase with hyphens

**Name** → `devshell-backend`
- Display name of the project
- Usually same as artifact
- Used in logs and Spring Boot banner

**Description** → `DevShell - Project Environment Manager`
- Just a human readable description
- Shows up in pom.xml, no functional impact

**Package Name** → `com.devshell.devshell-backend`
- The root Java package for all your classes
- Combines group + a sub-identifier
- All your Java files will live under this package
- Example: `com.devshell.devshell-backend.controller.HomeController`

## JAR vs WAR Packaging

| | JAR | WAR |
|---|---|---|
| Full Form | Java ARchive | Web ARchive |
| Server | Embedded Tomcat inside | Needs external Tomcat/JBoss |
| How to run | `java -jar app.jar` | Deploy into external server |
| Style | Modern | Old-school enterprise |
| Deployment | Railway, Render, anywhere | Legacy infrastructure only |

**Use JAR always for new projects.**

Analogy:
- JAR = Food truck (everything inside, just drive and serve)
- WAR = Restaurant building (set up the building first, then bring the food)

---

## Maven vs Gradle

| | Maven | Gradle |
|---|---|---|
| Config file | pom.xml | build.gradle |
| Syntax | XML | Groovy/Kotlin DSL |
| Industry usage | More common in Java enterprise | More common in Android/Kotlin |
| Help online | Easier to find | Slightly harder for beginners |

**Use Maven for DevShell** — more widely used in Java backend companies.

## application.properties

Using `application.properties` for DevShell configuration.
```properties
server.port=8080
spring.data.mongodb.uri=mongodb://localhost:27017/devshell
spring.application.name=devshell-backend
```

**Why properties works fine:**
- Simple flat key=value format
- Easy to read for beginners
- No indentation errors to worry about
- Does the exact same job as YML

## Why Spring Security Was NOT Added Yet

Spring Security blocks ALL routes by default the moment it's added.
Every request returns 403 Forbidden until configured.
As a beginner this causes confusion when you're just trying to test basic APIs.

Add Security later when you're ready to build:
- Login / Register API
- JWT filter
- Protected routes

# First Controller — HomeController.java

Location: `src/main/java/com/devshell/backend/HomeController.java`
```java
package com.devshell.backend;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class HomeController {

    @GetMapping("/")
    public String home() {
        return "DevShell is alive";
    }
}
```

**Annotations explained:**

`@RestController`
- Marks this class as a REST API controller
- Every method returns data directly (not a view/template)
- Combination of @Controller + @ResponseBody

`@GetMapping("/")`
- Maps HTTP GET requests to the `/` route
- When browser hits localhost:8080/ this method runs

# How to Run
```bash
mvn spring-boot:run
```

Then open browser: `http://localhost:8080`

**White Label Error Page** = Spring Boot is running correctly, just no routes exist yet. This is expected before adding controllers.

**"DevShell is alive"** = First endpoint working. Day 1 complete.

# Key Takeaways
- Spring Initializr generates the entire project skeleton — you just configure and download
- JAR is the modern packaging choice — embedded server, just run it
- application.properties is simple and works perfectly fine for Spring Boot config
- White Label Error Page is not an error — it means Spring Boot is alive
- Don't add Spring Security until you're ready to implement auth
- Package name becomes the root of all your Java class paths
