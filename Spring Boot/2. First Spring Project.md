# Problem Summary

Understanding the Spring Boot entry point file and running the project for the first time.

Input:
- A fresh Spring Boot project generated from start.spring.io
- Java installed on machine

Output:
- Spring Boot server running on localhost:8080
- White Label Error Page confirming server is alive

Key requirement:
- Understand every line of the main application file before moving forward

---

# Entry Point — Main Application File

Location: `src/main/java/com/your-package/DemoApplication.java`
```java
package com.example.demo;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class DemoApplication {

    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }

}
```

---

# Line by Line Breakdown

## `package com.example.demo;`
- The address/location of this file in the project
- Matches the actual folder structure on disk
- Convention: same as your group + artifact from Spring Initializr

## `import ...`
- Bringing in Spring Boot libraries to use in this file
- Same concept as `import axios from 'axios'` in React

## `@SpringBootApplication`
- An **annotation** — the `@` symbol means annotation in Java
- Think of annotations as instructions you stick on top of something to give Spring extra info
- This one annotation does 3 things internally:
  - Scans all your files for controllers, services etc.
  - Auto-configures sensible defaults
  - Marks this as a configuration class
- **One line that boots up the entire Spring framework**

## `public static void main(String[] args)`
- Starting point of any Java program
- Java looks for this exact method signature when you hit Run
- Same concept as `index.js` in Node.js

## `SpringApplication.run(DemoApplication.class, args)`
- The line that actually **starts the server**
- Reads all annotations, scans everything, starts embedded Tomcat
- `DemoApplication.class` = passing the class itself as a reference (not an instance)

# Running the Project
```bash
mvn spring-boot:run
```

Then open browser: `http://localhost:8080`

---

# White Label Error Page

**This is NOT a real error**

Spring Boot is saying: *"I'm alive but you haven't told me what to show here."*

| State | Meaning |
|---|---|
| White Label page shows | Server is running, no routes defined yet |

Analogy: Like setting up React Router but defining zero routes — the app runs but nothing renders.

---

# Default Port

- Spring Boot runs on `8080` by default (embedded Tomcat)
- Change it in `application.properties` if needed:
```properties
server.port=9090
```

# Mental Model

| Step | What Happens |
|---|---|
| `mvn spring-boot:run` | Server starts |
| Visit `localhost:8080` | Hits the server |
| White Label page shows | Server works, no routes defined yet |

# Key Takeaways
- The main file is the ignition switch — run it and the server is live
- `@SpringBootApplication` is one annotation that does the work of three
- White Label Error Page = Spring Boot is alive, not a real error
- Default port is 8080, change anytime in `application.properties`
- Java annotations (`@`) are like instructions you attach to classes and methods
