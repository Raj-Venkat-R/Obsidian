# What is Spring Boot

- A framework that eases building APIs and backends using Java
- Key feature = **annotations** — they tell Spring the purpose of every class and method
- Without Spring Boot you'd have to manually configure everything
- `@SpringBootApplication` marks the project as a Spring Boot project, not plain Java

---

# Client Server Architecture

When you enter a URL in the browser:
1. Browser (client) sends a **request** to the server
2. Server processes it and sends back a **response**

| Caller | Returns |
|---|---|
| Website (browser) | HTML page (visual) |
| REST API (Postman/React) | Raw data (JSON, plain text) |

`@RestController` returns **data**, not pages.
The frontend (React later) consumes that data and decides how to display it.

# Entry Point — DemoApplication.java
```java
@SpringBootApplication
public class DemoApplication {

    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }

}
```

## Key Points

`@SpringBootApplication`
- Marks this as a Spring Boot project
- Scans all files in the package automatically for controllers, services etc.
- One annotation that does the work of three internally

`SpringApplication.run(DemoApplication.class, args)`
- `SpringApplication` is a class that comes from the Spring Boot library — you didn't write it
- `.run()` starts the server using the main class as entry point
- Spring then automatically finds all controllers via package scanning
- You never pass the controller manually — Spring finds it itself

Analogy:
```javascript
// Same idea as Express in Node.js
const app = express()
app.listen(3000)
// You didn't write express, you just call it
```

# First Controller — HelloWorldController.java
```java
package com.example.demo;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class HelloWorldController {

    @GetMapping("/")
    public String hello() {
        return "Hello World";
    }
}
```

## Annotations Explained

`@RestController`
- Comes from the **Spring Web** dependency
- Tells Spring this class is a REST API controller
- Every method returns data directly (not a view/template)
- Combination of `@Controller` + `@ResponseBody`

`@GetMapping("/")`
- Maps HTTP GET requests to the `/` endpoint
- When Postman or browser hits `localhost:8080/` this method runs
- `"/"` is the **endpoint**

# Endpoints

An endpoint is a URL path your API exposes.
Hit that endpoint → get a response back.

Later the response won't be a hardcoded string — it'll be real data fetched from MongoDB.

| Endpoint | Method | Returns |
|---|---|---|
| `/` | GET | "Hello World" (practice) |
| `/api/projects` | GET | All projects from DB |
| `/api/projects/123` | GET | One specific project |
| `/api/secrets` | POST | Save a new secret |

# HTTP Methods

| Method | Annotation | Purpose |
|---|---|---|
| GET | `@GetMapping` | Fetch / read data |
| POST | `@PostMapping` | Create new data |
| PUT | `@PutMapping` | Update — full replace |
| PATCH | `@PatchMapping` | Update — partial only |
| DELETE | `@DeleteMapping` | Delete data |

**GET, POST, PUT, DELETE** are the 4 main ones. PATCH is used less frequently.

## PUT vs PATCH — Key Difference

**PUT** — send the entire object, everything gets overwritten:
```json
{
  "name": "Arun",
  "phone": "9999999999",
  "address": "Chennai"
}
```

**PATCH** — send only the field that changed:
```json
{
  "phone": "9999999999"
}
```
Everything else stays untouched.

# Security (Coming Later)

Right now the API is completely open — anyone can hit any endpoint.

When Spring Security + JWT is added later:

| Without Security | With Security |
|---|---|
| Anyone hits `/api/projects` → gets data | Must send valid JWT token |
| No idea who is calling | Server knows exactly who is calling |
| No restrictions | Roles checked — admin, developer, readonly |

# Key Takeaways
- Spring Boot's key feature is annotations — they define the purpose of every class and method
- `@SpringBootApplication` = this is a Spring Boot project, scan everything automatically
- `SpringApplication.run()` starts the server — it comes from Spring Boot library, not your code
- Spring finds your controllers automatically — you never pass them manually
- `@RestController` returns data, not HTML pages
- Every endpoint is just a method with an annotation on top
- GET = fetch, POST = create, PUT = full update, PATCH = partial update, DELETE = delete
- Postman is used to test APIs during development
