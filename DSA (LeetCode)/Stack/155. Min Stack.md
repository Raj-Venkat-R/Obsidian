## Problem Summary
Design a stack that supports the following operations in constant time:

- push(val)
- pop()
- top()
- getMin()

`getMin()` must return the **minimum element currently in the stack**.

All operations must run in **O(1)** time.

---

## My First Thought (Initial Approach)
- Use a single stack to store elements.
- When `getMin()` is called, traverse the stack to find the minimum.

This works but requires **O(n)** time for each `getMin()` call, which violates the problem constraint.

---

## Key Observation
To achieve constant time minimum retrieval, we maintain **two stacks**:

1. Main stack  
   - Stores all values normally.

2. Min stack  
   - Stores only the **current minimum values**.

When a new value is pushed:
- If it is smaller than or equal to the current minimum, push it to `minStack`.

When popping:
- If the popped value equals the minimum, remove it from `minStack`.

Thus, the top of `minStack` always holds the current minimum.

---

## Final Approach (Step-by-Step in English)

1. Initialize two stacks:
   - `stack` for all elements
   - `minStack` for tracking minimums

2. Push operation:
   - Push value to `stack`
   - If `minStack` is empty or value ≤ current minimum, push it to `minStack`

3. Pop operation:
   - If top of `stack` equals top of `minStack`, pop from `minStack`
   - Pop from `stack`

4. Top operation:
   - Return the top of `stack`

5. getMin operation:
   - Return the top of `minStack`

## Java Code (Final)

```java
class MinStack {
    Stack<Integer> stack;
    Stack<Integer> minStack;

    public MinStack() {
        stack = new Stack<>();
        minStack = new Stack<>();
    }

    public void push(int val) {
        stack.push(val);

        if (minStack.isEmpty() || val <= minStack.peek()) {
            minStack.push(val);
        }
    }

    public void pop() {
        if (stack.peek().equals(minStack.peek())) {
            minStack.pop();
        }
        stack.pop();
    }

    public int top() {
        return stack.peek();
    }

    public int getMin() {
        return minStack.peek();
    }
}
```

## Time & Space Complexity

Time Complexity:
- push → O(1)
- pop → O(1)
- top → O(1)
- getMin → O(1)

Space Complexity:
- O(n)

## Patterns Learned

- Auxiliary stack for tracking minimum values
- Monotonic stack behavior
- Maintaining extra structure for constant-time queries

---

## Common Mistakes to Avoid

- Using `<` instead of `<=` when pushing to `minStack`
- Forgetting to pop from `minStack` when the minimum element is removed
- Calling `peek()` on an empty stack
- Using a PriorityQueue instead of a stack (breaks O(1) requirement)
