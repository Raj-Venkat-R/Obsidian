## Problem Summary
Given an array of intervals `intervals` where:

```
intervals[i] = [start, end]
```

Merge all overlapping intervals and return the result.

---

## Key Observation
Intervals must be processed in **sorted order** to correctly detect overlaps.

Without sorting:
- Overlapping intervals may not be adjacent
- Merging logic fails

---

## Final Approach (Step-by-Step in English)

1. Sort intervals based on start time

2. Initialize:
   ```
   current = first interval
   ```

3. Traverse remaining intervals:
   - If overlap:
     ```
     next.start ≤ current.end
     ```
     → merge:
     ```
     current.end = max(current.end, next.end)
     ```
   - Else:
     ```
     add current to result
     move current = next
     ```

4. Add the last interval after loop

---

## Overlap Condition

```
next.start ≤ current.end
```

---

## Example

Input:

```
[[1,3],[2,6],[8,10],[15,18]]
```

Process:

```
[1,3] & [2,6] → merge → [1,6]
[8,10] → no overlap → add [1,6]
[15,18] → no overlap → add [8,10]
```

Output:

```
[[1,6],[8,10],[15,18]]
```

---

## Java Code (Final)

```java
class Solution {
    public int[][] merge(int[][] intervals) {

        Arrays.sort(intervals, (a, b) -> a[0] - b[0]);

        List<int[]> res = new ArrayList<>();

        int[] current = intervals[0];

        for(int i = 1; i < intervals.length; i++){

            int[] next = intervals[i];

            if(next[0] <= current[1]){
                current[1] = Math.max(current[1], next[1]);
            } else {
                res.add(current);
                current = next;
            }
        }

        res.add(current);

        return res.toArray(new int[res.size()][]);
    }
}
```

## Patterns Learned

- Sorting intervals before processing
- Greedy merging
- Handling overlapping ranges
- Boundary tracking

---

## Common Mistakes to Avoid

- Not sorting intervals
- Starting loop from index 0 instead of 1
- Forgetting to add the last interval
- Incorrect overlap condition
- Not using `max()` when merging
